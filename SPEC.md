# Техническое задание: Платформа технических интервью

## О проекте

Информационная система для автоматизации процессов технического интервью и код-ревью. Позволяет проводить онлайн-собеседования IT-специалистов с совместным редактированием кода в реальном времени, безопасным выполнением кода, автоматическим статическим анализом и асинхронным код-ревью с формированием итогового отчёта.

Проект — дипломная работа. Не выливается в продакшн, разворачивается локально через `docker compose up`.

## Стек технологий

**Backend:** Java 21, Spring Boot 3, Spring Cloud Gateway, Spring Security
**База данных:** PostgreSQL 16 (паттерн «база данных на сервис», 6 логических схем)
**Брокер сообщений:** Apache Kafka
**Кэш:** Redis 7
**Объектное хранилище:** MinIO (S3-совместимое)
**Анализ кода:** JavaParser, Checkstyle, PMD
**Sandbox для выполнения кода:** Docker (Docker-in-Docker для запуска контейнеров с пользовательским кодом)
**Frontend:** React 18 + TypeScript, Monaco Editor, Yjs (CRDT), Recharts, Tailwind CSS
**Сборка:** Maven (backend), Vite (frontend)
**Развёртывание:** Docker Compose

## Архитектура — 10 микросервисов

1. **api-gateway** — Spring Cloud Gateway, проверка JWT, маршрутизация запросов
2. **auth-service** — регистрация, авторизация, выдача JWT, refresh-токены, bcrypt с 12 раундами
3. **user-service** — управление пользователями, компании, роли (для администратора)
4. **subscription-service** — тарифы, подписки, обработка платежей через mock-шлюз с webhook
5. **session-service** — CRUD сессий собеседования, библиотека задач, участники
6. **collaboration-service** — WebSocket-сервис для совместного редактирования через Yjs CRDT, синхронизация через Redis pub/sub
7. **execution-service** — выполнение пользовательского кода в изолированных Docker-контейнерах с лимитами CPU/RAM/без сети, поддержка Java/Python/JavaScript/Go/C++
8. **analysis-service** — статический анализ кода: AST через JavaParser, метрики (цикломатическая и когнитивная сложность), Checkstyle и PMD для выявления проблем
9. **review-service** — комментарии к коду, оценки по критериям, итоговый вердикт
10. **report-service** — генерация PDF-отчётов, экспорт в JSON, сохранение в MinIO
11. **notification-service** — рассылка email-уведомлений, WebSocket-нотификации (опционально SMTP-mock)
12. **analytics-service** — сбор событий из Kafka, предагрегированные метрики, аудит-лог

(Технически 12 сервисов с учётом gateway и analytics — но в дипломе называю 10 основных.)

Микросервисы общаются:
- через REST API (синхронно)
- через Kafka-события (асинхронно): `UserRegistered`, `SessionCreated`, `SessionCompleted`, `ReviewCompleted`, `PaymentReceived` и т.д.

## Роли пользователей

- **Кандидат** — соискатель, проходящий интервью
- **Интервьюер** — проводит сессию, делает код-ревью
- **HR-менеджер** — управляет подпиской компании, создаёт сессии
- **Администратор** — управляет пользователями платформы, смотрит аналитику

## Функциональность

### Кандидат
- Регистрация и авторизация
- Получение приглашения на сессию по email
- Подключение к сессии в назначенное время
- Совместное редактирование кода с интервьюером (Yjs)
- Запуск кода с просмотром результатов выполнения

### Интервьюер
- Создание сессий с выбором кандидата, времени, языка, задачи
- Управление библиотекой задач (CRUD)
- Проведение сессии: совместное редактирование, просмотр анализа кода в реальном времени
- Код-ревью завершённой сессии: комментарии к строкам, оценки по 4 критериям, итоговый вердикт
- Просмотр итогового отчёта, экспорт в PDF/JSON

### HR-менеджер
- Управление сессиями компании
- Управление подпиской: выбор тарифа (Старт/Команда/Бизнес/Корпорация), оплата, продление, отмена
- Просмотр отчётов по сессиям компании

### Администратор
- Управление пользователями (создание, изменение ролей, блокировка, поиск)
- Просмотр аналитики платформы: KPI, графики (Recharts), фильтры
- Просмотр журнала событий

## База данных

22 таблицы распределены по 6 схемам PostgreSQL:

- **auth_service:** users, roles, refresh_tokens, companies
- **subscription_service:** subscriptions, tariffs, payments
- **session_service:** sessions, session_participants, tasks, code_snapshots, session_events, task_categories, task_categories_link
- **review_service:** reviews, comments, code_executions, code_analysis
- **report_service:** reports
- **notification_service:** notifications
- **analytics_service:** analytics_events, analytics_metrics_daily, audit_log

Первичные ключи — UUID, генерируются на стороне сервисов до сохранения.

## Безопасность

- Пароли хранятся как bcrypt-хэши (12 раундов)
- JWT-токены подписываются HS256, срок действия 15 минут
- Refresh-токены хранятся в БД, срок 30 дней
- API Gateway проверяет JWT для всех непубличных маршрутов
- Роли проверяются на уровне Gateway (RBAC)
- HTTPS не требуется (локальная разработка), но код должен это поддерживать
- Sandbox для выполнения кода: read-only filesystem, без сети, лимиты по CPU/памяти/процессам через cgroups

## Frontend

10 основных экранов:
1. Регистрация
2. Авторизация
3. Главная (список сессий)
4. Создание сессии
5. Проведение интервью (с Monaco Editor, видеопанель — заглушка, чат, вывод выполнения, анализ кода)
6. Код-ревью (код + комментарии + рубрика оценок)
7. Итоговый отчёт
8. Управление подписками (4 тарифа)
9. Управление пользователями (для админа)
10. Аналитика (для админа, с графиками Recharts)

Маршрутизация по ролям: после логина пользователь редиректится в раздел, соответствующий роли.

## Что должно быть в финальном виде

- `docker-compose.yml` в корне, запускающий **всю систему одной командой** `docker compose up`
- Каждый микросервис — отдельный модуль (Maven multi-module проект, либо отдельные репозитории — на усмотрение)
- Минимум один сценарий "от и до" работает end-to-end: регистрация → создание сессии → проведение интервью с выполнением кода → ревью → отчёт
- Базовые юнит-тесты для ключевой бизнес-логики (auth, code execution, code analysis)
- Документация API через OpenAPI/Swagger у каждого сервиса
- README.md с инструкцией запуска

## Что НЕ требуется

- Реальная видеосвязь (WebRTC) — оставить заглушку с надписями «Кандидат» / «Интервьюер»
- Реальная интеграция с платёжным шлюзом — mock с webhook-подтверждением
- Реальная отправка email — log в консоль или MailHog для разработки
- Kubernetes, Helm-чарты, CI/CD — только Docker Compose
- HTTPS-сертификаты — http://localhost достаточно
- Высокая доступность, репликация БД, шардирование — не для локальной разработки
- Безопасность продакшн-уровня (rate limiting на gateway, защита от DDoS) — упрощённо

## Этапы реализации (рекомендация)

1. **Инфраструктура:** docker-compose с PostgreSQL, Redis, Kafka, MinIO
2. **auth-service + api-gateway:** регистрация, авторизация, JWT
3. **user-service + frontend:** базовый личный кабинет, маршрутизация по ролям
4. **session-service:** CRUD сессий, библиотека задач
5. **collaboration-service:** WebSocket + Yjs для совместного редактирования
6. **execution-service:** Docker-sandbox для запуска кода
7. **analysis-service:** статический анализ через JavaParser/Checkstyle/PMD
8. **review-service + report-service:** комментарии, оценки, генерация PDF
9. **subscription-service + notification-service:** подписки и уведомления
10. **analytics-service:** сбор метрик, дашборд для админа

Каждый этап завершается рабочим состоянием: можно запустить, проверить, закоммитить.
