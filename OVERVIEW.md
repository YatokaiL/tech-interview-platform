# Платформа автоматизированных технических интервью

Микросервисная система: **12 бэкенд-сервисов + React-фронтенд**, поднимается локально одной командой `docker compose up`. Java 21 + Spring Boot 3.5, PostgreSQL (схема-на-сервис), Kafka, Redis, MinIO, MailHog, Ollama.

## Архитектура

```
                    ┌─────────────┐
   Браузер ───────► │ api-gateway │ (8080)  ◄── единая точка входа, JWT, CORS, routing
                    └──────┬──────┘
        ┌──────────────────┼─────────────────────────────┐
        ▼                  ▼                              ▼
  auth (8081)        бизнес-сервисы              collaboration (8085)
  user (8082)        session (8084)              ↕ WebSocket (код + звонок)
  subscription(8083) execution (8086)
                     analysis (8087)
                     review (8088)
                     report (8089)
                     notification (8090)
                     analytics (8091)
        │
        └──► Kafka (события) ◄── analytics + notification
  Инфраструктура: PostgreSQL · Redis · Kafka · MinIO · MailHog · Ollama
```

## Инфраструктура

PostgreSQL 16 (отдельная схема под каждый сервис), Redis (хранение refresh-токенов), Kafka в режиме KRaft с предсозданными топиками, MinIO (объектное хранилище), MailHog (перехват почты), Ollama (локальная LLM). Всё связано через docker-compose с healthcheck'ами.

## Бэкенд-сервисы

| Сервис | Порт | Что делает |
|---|---|---|
| **api-gateway** | 8080 | Spring Cloud Gateway (reactive). Единый вход, маршрутизация на все сервисы, CORS, проброс JWT, проксирование WebSocket. |
| **auth-service** | 8081 | Регистрация/логин, JWT (HS256, access+refresh), хранение refresh в Redis, logout. Публикует `user-registered`. |
| **user-service** | 8082 | Профили пользователей и компаний, роли (CANDIDATE/INTERVIEWER/HR_MANAGER/ADMIN), блокировка, поиск, публичный профиль для других сервисов. |
| **subscription-service** | 8083 | 4 тарифа (START/TEAM/BUSINESS/ENTERPRISE), подписки, mock-оплата через webhook. Публикует `payment-received`. |
| **session-service** | 8084 | Интервью-сессии (планирование, старт/завершение), банк задач с категориями, снимки кода (snapshots) и события сессии. Публикует `session-created`/`session-completed`. |
| **collaboration-service** | 8085 | Realtime-комната по WebSocket: совместное редактирование кода, чат, presence. Плюс сигнальный канал звонка (`/ws/calls`). |
| **execution-service** | 8086 | Запуск кода в изолированном Docker-контейнере (Java/Python/JS/Go/C++), без сети, с лимитами и таймаутом. Async с поллингом. Публикует `code-executed`. |
| **analysis-service** | 8087 | Статанализ Java: JavaParser (цикломатическая/когнитивная сложность, оценка Big-O), Checkstyle, PMD. Публикует `analysis-completed`. |
| **review-service** | 8088 | Ревью по рубрике (4 оценки + вердикт HIRE/NO_HIRE/MAYBE), комментарии к строкам, авто-ревью (эвристика + локальная LLM через Ollama). Публикует `review-completed`. |
| **report-service** | 8089 | Сводный отчёт по сессии: PDF (OpenPDF, кириллица) и JSON, заливка в MinIO, скачивание. |
| **notification-service** | 8090 | Слушает 5 Kafka-топиков → in-app уведомления (колокольчик) + письма через MailHog. |
| **analytics-service** | 8091 | Сток всех событий из Kafka в event-store, агрегированные метрики, админ-дашборд и журнал событий. |

## Фронтенд (React 18 + TS + Vite + Tailwind + shadcn/ui)

- Авторизация с авто-refresh токенов, роутинг по ролям.
- Управление пользователями, задачами, сессиями.
- **Комната интервью**: Monaco-редактор с realtime-синхронизацией, чат, запуск кода, панель анализа, видеозвонок с демонстрацией экрана.
- Страница ревью с рубрикой и авто-генерацией, скачивание PDF/JSON.
- Подписки и оплата, колокольчик уведомлений.
- Админ: дашборд аналитики (графики Recharts) + журнал событий.

## Ключевой сценарий — видеозвонок

WebRTC peer-to-peer 1:1 без медиасервера. Сигналинг (offer/answer/ICE) — через WebSocket collaboration-service.

1. Приглашение на собес → уведомление кандидату.
2. Старт сессии → **лобби**: предпросмотр, тумблеры микрофона/камеры.
3. **Разговор** (видео обоих) → интервьюер жмёт «Пригласить на тех. секцию».
4. Открывается **редактор кода**, звонок уезжает в плавающее окно (PiP).
5. Переключение «Разговор ↔ Код» в любой момент — связь не рвётся. Демонстрация экрана работает.

## Сквозные решения

- **Событийная интеграция** через Kafka (9 топиков): сервисы слабо связаны, аналитика и уведомления — чистые потребители.
- **Async + поллинг** для долгих операций (запуск кода, анализ) с планированием фоновой задачи после коммита транзакции.
- **Авто-ревью на LLM**: локальная Ollama (qwen2.5-coder), с эвристическим фоллбэком.
- **Изоляция выполнения кода**: Docker-контейнеры с `cap-drop ALL`, без сети, no-new-privileges.
- **Безопасность**: JWT-ресурс-серверы во всех сервисах, межсервисные вызовы с пробросом токена или минтингом сервисного.

---

Итого: **12 микросервисов + фронтенд**, событийная архитектура, изолированный запуск кода, LLM-ревью, отчёты, подписки, уведомления, аналитика и видеосвязь с демонстрацией экрана — всё локально через Docker Compose.
